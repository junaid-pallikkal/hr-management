# Build discipline

## Scope

- Create only what was asked. No extra pages, features, files, packages or settings.
- Have a better idea? Suggest it first and wait for the answer.
- Keep it simple. Pick the simplest solution that works.
- Reuse existing components before making new ones.
- Don't refactor or change code unrelated to the task.
- Ask before installing any new dependency.

## Hackathon mode

- We have 4 hours. A working, demo-ready flow beats perfect code.
- Build the main flow end to end first, then polish.
- Use realistic sample data so the demo looks real.
- Keep the app runnable at all times. Never leave it broken between tasks.
- Work in small steps. Update [TASKS.md](TASKS.md) after each one.
- Don't forget empty, loading and error states, and mobile layout.

## Replies

- Keep replies short and in simple language.
- Say what you did and what I need to check.
- If something is unclear, ask one short question. Don't guess.
- No long explanations or summaries unless asked.
