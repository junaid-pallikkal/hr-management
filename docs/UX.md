# Workflow and wording rules

## Who we build for

- The end user is not a developer. Every screen, label and message must make sense to a non-technical person.
- Use simple, everyday words everywhere: UI text, errors and your own explanations.
- Avoid technical terms. Say "Couldn't save. Please try again" instead of "500 server error".

## Workflow first

- Before building a feature, think of the easiest workflow. Fewest clicks, fewest decisions.
- Pick sensible defaults so the user doesn't fill in everything.
- Every list has a friendly empty state with one clear action.
- Show a loading state while waiting.
- Show a short toast after every action (success or failure).
- Ask for confirmation before deleting. Offer undo where it's easy.
- Show errors next to the field with the problem, in plain words.
- Work well on mobile and desktop.

## Text

- Never add descriptions or subtitles under page or section headers.
- Add a description only when the user truly can't understand without it.
- Keep labels short: 1–3 words where possible.

## Create and edit

- About 10 fields or fewer and it fits: use a popup modal.
- More than 10 fields, or long, or hard to use in a popup: use a separate page.
- Create and edit forms look the same: same layout, same fields, same buttons in the same places.
